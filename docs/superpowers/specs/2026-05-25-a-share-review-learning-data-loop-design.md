# A 股荐股 APK 复盘学习数据闭环设计

## 背景

当前 APK 已经具备每日 8:30 准备名单和 9:25 集合竞价确认的荐股流程，并通过 GitHub Pages 读取每日 JSON 数据。下一阶段目标不是把系统包装成保证收益的黑箱模型，而是把它升级为可复盘、可沉淀、可修正规则的学习系统。

这个设计借鉴专业量化系统的基本思想：数据留痕、因子拆解、结果验证、风险控制和持续反馈。它不试图复刻任何机构策略，也不承诺投资收益。

## 第一版目标

第一版做成数据闭环 MVP。核心目标是让每一条推荐都能被记录、验证、解释和反向修正规则。

第一版必须支持：

- 继续保留 8:30 准备推荐和 9:25 竞价确认。
- 首页按北京时间和交易阶段自动切换展示重点内容。
- 本地保存每日推荐快照。
- 首推票重点复盘，备选票简要复盘。
- 用次日收益作为主要验证目标。
- 系统理论表现和用户真实交易表现分开打标签。
- 用户可手动录入真实交易日志。
- 失败时做多因子归因。
- 生成待确认的规则修改建议草案。
- 个人交易记录只保存在手机本地。
- 历史记录长期保留，并支持导出。

## 非目标

第一版不做以下能力：

- APK 直接写入 GitHub 仓库。
- 自动修改线上选股规则配置。
- 机器学习自动调参。
- 自动交易或券商接口下单。
- 上传用户真实交易日志到云端。
- 承诺推荐收益或给出保证性结论。

## 本地数据类型

### 推荐快照

推荐快照用于保存系统在当时可见数据下做出的推荐结果，避免后续数据变化后无法复盘原始判断。

每个交易日保存：

- 交易日期，按北京时间自然日和 A 股交易日展示。
- 8:30 准备名单。
- 9:25 竞价确认名单。
- 每个阶段的首推票和备选票。
- 股票代码、股票名称、所属题材。
- 总分和子因子分数。
- 推荐理由。
- 数据状态，例如成功、失败、缺关键数据、不推荐。
- 生成时间和数据更新时间。

### 复盘结果

复盘结果记录推荐后的表现和系统解释。

每个推荐股票保存：

- 次日盘中临时观察。
- 次日收盘正式复盘。
- 第三天早上消息面和风险补充。
- 系统理论收益。
- 成功、一般、失败标签。
- 是否跑赢大盘。
- 是否跑赢所属板块。
- 多因子归因。
- 对应的规则修正建议。

成功标签采用分层判断：

- 次日理论收益大于 2%：成功。
- 次日理论收益在 0% 到 2% 之间：一般。
- 次日理论收益小于 0%：失败。

同时记录相对表现，包括是否跑赢主要指数和所属板块。

### 真实交易日志

真实交易日志只保存在手机本地，不上传到 GitHub。

用户可以为每只推荐票记录：

- 是否买入。
- 买入价。
- 卖出价。
- 仓位。
- 买入时间。
- 卖出时间。
- 固定原因选项。
- 文字备注。

固定原因选项包括但不限于：

- 按计划执行。
- 追高。
- 低吸。
- 打板。
- 止损。
- 止盈。
- 情绪冲动。
- 临盘放弃。
- 未达到买点。

系统需要区分两个标签：

- 系统推荐标签：衡量股票是否选对。
- 真实交易标签：衡量用户执行是否有效。

如果股票次日表现很好但真实交易亏损，应记录为系统推荐成功、真实交易失败，并分析买点、卖点、仓位、纪律和情绪原因。

### 规则建议草案

规则建议草案由复盘模块生成，先保存为待确认状态。

建议类型包括：

- 子因子权重调整。
- 过滤规则新增。
- 过滤规则收紧。
- 过滤规则放宽。
- 特定市场阶段下的策略切换建议。
- 个人交易纪律建议。

规则建议状态包括：

- 待确认。
- 已确认。
- 已驳回。
- 暂缓。

个人交易纪律建议只保存在手机本地。选股规则和权重建议在用户确认后先保存在手机本地，后续由人工同步到 GitHub 配置，不在第一版中由 APK 自动写入远程仓库。

## 页面设计

### 首页

首页按北京时间和交易阶段自动切换优先内容：

- 早上：优先展示 8:30 准备推荐和 9:25 竞价确认。
- 盘中：展示昨日推荐票的临时观察。
- 收盘后：优先展示正式复盘。
- 第三天早上：展示消息面、情绪延续和风险补充。

首页必须突出首推票。8:30 和 9:25 都应有独立首推位置。如果当日不推荐，需要明确展示不推荐原因。

### 历史页

历史页按月、周、日折叠展示。

每个交易日下包含：

- 8:30 准备名单。
- 9:25 竞价确认名单。
- 首推复盘。
- 备选简要复盘。
- 用户真实交易记录入口。
- 规则建议入口。

过期日期的信息默认折叠，用户可以展开查看。

### 复盘页

复盘页以首推票为重点。

首推票展示：

- 推荐阶段。
- 推荐理由。
- 当时子因子分数。
- 次日理论收益。
- 成功、一般、失败标签。
- 跑赢大盘和板块情况。
- 多因子归因。
- 规则修正建议。
- 真实交易结果。

备选票展示简化版复盘，重点保留理论收益、标签和主要归因。

### 交易记录页

交易记录页用于录入和查看用户真实交易。

它应支持：

- 针对推荐票快速录入买卖记录。
- 修改和删除交易记录。
- 固定原因选项。
- 文字备注。
- 系统理论表现和真实交易表现对比。

### 规则建议页

规则建议页集中展示待确认建议。

每条建议展示：

- 触发原因。
- 涉及因子或过滤规则。
- 建议动作。
- 适用市场阶段。
- 证据样本。
- 确认、驳回、暂缓操作。

## 自动触发和补偿刷新

系统按北京时间处理日期和交易阶段。不能按美国时间或 UTC 日期决定首页状态。

每日闭环分为 5 个阶段：

1. 8:30 准备推荐。
2. 9:25 竞价确认。
3. 次日盘中临时观察。
4. 次日收盘正式复盘。
5. 第三天早上消息面和风险补充。

APK 打开时必须执行补偿刷新：

- 8:35 打开时，如果没有 8:30 结果，应补生成或补展示准备名单。
- 9:26 打开时，如果已有 8:30 池子，应补生成或补展示 9:25 确认。
- 次日盘中打开时，应补展示临时观察。
- 次日收盘后打开时，应补生成正式复盘。
- 第三天早上打开时，应补充消息和风险影响。

如果网络失败，优先展示本地最后一次快照，并明确标记数据状态。

## 评分和归因框架

荐股评分继续使用当前大框架：

- 20% 交易主逻辑。
- 20% 游资逻辑。
- 30% 跨平台讨论热度。
- 30% 量化维度。

交易主逻辑包含：

- 市场环境。
- 题材强度。
- 成交和换手。
- 人气龙头。
- 未过热。
- 风险过滤。
- 竞价确认。

游资逻辑按既定六大思路维度拆分。

跨平台讨论热度包含：

- 问财。
- 东方财富股吧。
- 微博财经生态。

量化维度按既定六个量化维度拆分。

复盘时不只看总分，还要检查每个子因子判断是否被次日表现验证。

典型归因包括：

- 高热度失败：检查是否热度过热、一致性太强、接盘风险上升。
- 竞价放量失败：检查是否高开过多、承接不足、虚假强势。
- 量化高分失败：检查是否短线情绪压过量化信号。
- 游资逻辑高分失败：检查席位、龙虎榜、资金接力证据是否不足。
- 题材强度失败：检查主线是否一日游、轮动太快、龙头失效。
- 风控失败：检查是否应被过热、利空、流动性或市场退潮过滤。

## 规则修正策略

规则修正按市场阶段切换风格：

- 退潮期：更保守，少做、严过滤、降低频率。
- 主升期：更进攻，强化龙头、竞价确认和题材延续。
- 震荡期：平衡，重视性价比和失败代价。

系统优化目标为综合目标：

- 提高首推胜率。
- 提高平均收益。
- 降低最大回撤。

最大回撤具有一票否决权。任何提高收益的建议，如果显著扩大连续失败或大亏风险，都不能自动进入推荐规则。

样本足够的判断需要同时考虑：

- 推荐次数。
- 交易日数量。
- 市场阶段覆盖。

在样本不足时，规则建议只能作为经验提示，不作为统计结论。

## 数据存储和隐私

数据采用分层存储：

- GitHub 和线上 JSON：公开行情、系统推荐、理论复盘所需的非隐私数据。
- 手机本地：用户真实交易记录、买卖价、仓位、原因备注、个人交易纪律建议。
- 后续可选：加密备份文件，用于换手机迁移。

第一版优先支持 CSV 导出，用于复盘分析。后续再增加加密备份文件。

## 风险和限制

第一版存在以下限制：

- 当前公开数据源不一定能完整覆盖集合竞价、龙虎榜、股吧、微博和问财热度。
- 复盘准确性依赖后续行情数据质量。
- 如果缺少足够历史样本，规则建议不能视为统计显著结论。
- 如果用户不持续记录真实交易，执行能力训练价值会下降。
- 系统是辅助决策和复盘工具，不是收益保证工具。

## 验收标准

第一版完成后，至少应满足：

- 首页能按北京时间展示当前交易阶段的重点内容。
- 每日推荐快照能保存到手机本地。
- 历史页能按月、周、日折叠查看。
- 首推票能生成重点复盘。
- 备选票能生成简要复盘。
- 次日理论收益能分为成功、一般、失败。
- 用户能录入真实买入、卖出、仓位、时间、原因和备注。
- 系统推荐标签和真实交易标签能分开展示。
- 失败推荐能生成多因子归因。
- 规则建议能进入待确认列表。
- 个人交易记录不会上传到 GitHub。
- 网络失败时能展示本地快照和数据状态。
